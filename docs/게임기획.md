# 스킬 크래프트 배틀 (가제) — 게임 기획서

## 한 줄 컨셉
"내가 그린 스킬로 싸운다." 코어 루프 = 그림판에서 스킬 창작 → QWER 4칸에 형평성 있게 배치 → 5분 안에 맞히고 피하는 손맛.

## 코어 설계
- 5v5, 3인칭, PC. 이동 방향키 / 점프 스페이스바 / 스킬 QWER 4슬롯. 5분×3라운드.
- 스킬 제작(심장): 스킬 세팅 창(그림판)에서 모양 그리기 + 발사 형태 + 데미지(1~100) + 범위 설정.
- 형평성 원칙: 데미지 약할수록 쿨 짧게, 셀수록 쿨 길게. 범위 크고 세면 쿨 길고 발동 느림(피하기 쉬움). 범위 작고 세면 발동 빠름(피하기 어려움).
- 맵: 거대한 원룸 한 칸, 소형 인간들이 싸움. 캐릭터/속도는 멧챠 카멜레온풍.
- 자기장: 시간 지나면 배그처럼 안전구역 축소 → 강제 교전.
- 이펙트: 마법봉으로 마법 쓰는 연출. 회피: 이동 + 점프.

## 밸런스 공식 (제안)
공통 예산 100pt. 비용 = 데미지 + (범위×계수). 남은 예산으로 쿨/발동속도 자동 결정.

## ✅ 결정됨 — 그림의 역할: 하이브리드 (2026-07-31)
그림은 **겉모습 + 히트박스 "형태" 태그**까지 담당한다. 세기는 절대 담당하지 않는다.

### 대원칙 (밸런스 안전장치)
> **그림은 모양을 바꾸고, 수치는 세기를 바꾼다.**
> 스킬의 총 유효 판정 면적은 에디터의 `범위` 슬라이더 값으로 **정규화**된다.
> 어떤 그림을 그리든 같은 범위 값이면 총 면적은 같다. 그림은 그 면적을 어떤 모양으로 배분할지만 정한다.
> → 얇은 선 하나로 맵 관통 같은 악용이 원천 차단된다.

### 파이프라인
1. 유저가 그림판(32×32 그리드)에 그림 → 픽셀 마스크
2. 마스크에서 **지표 4개** 계산
   - 채움률 = 칠한 픽셀 / 바운딩박스 면적
   - 종횡비 = 바운딩박스 가로/세로
   - 복잡도 = 둘레² / 면적 (뾰족할수록 큼)
   - 덩어리 수 = 연결 요소(connected components) 개수
3. 지표 → **형태 태그 1개** 판정 (아래 표)
4. 태그 → 히트박스 프리셋 선택, 크기는 `범위` 값으로 정규화
5. 원본 그림은 투사체 스프라이트/이펙트 텍스처로 그대로 사용 (겉모습)

### 형태 태그 표 (초안 — 밸런스 담당이 수치 조정)
| 태그 | 판정 조건 | 히트박스 형태 | 체감 |
|---|---|---|---|
| 길쭉함 | 종횡비 ≥ 2.5 또는 ≤ 0.4 | 직선 관통형(캡슐), 폭 좁고 사거리 김 | 조준 어려움, 맞히면 시원함 |
| 둥긂 | 종횡비 0.7~1.4 & 채움률 높음 | 원형 폭발 | 무난, 기본값 |
| 뾰족함 | 복잡도 높음 | 부채꼴 다단 히트 | 근거리 난사형 |
| 흩어짐 | 덩어리 2개 이상 | 산탄 다발(작은 원 N개) | 견제형 |

애매하면 **둥긂(기본값)** 으로 폴백. 에디터에서 판정된 태그를 실시간으로 보여줘 유저가 예측 가능하게 한다.

### 나중 확장 여지
프로토타입에서 재미가 확인되면 태그를 늘리거나(회전/부메랑/설치), 태그별 미세 파라미터를 그림에서 더 뽑는 방향으로 확장. 픽셀 모양 그대로를 히트박스로 쓰는 완전 B안은 채택하지 않는다.

## ✅ 결정됨 — 엔진/시점: Godot 4, **3D 3인칭** (2026-07-31, 사용자 확정)
프로토타입부터 **3D 3인칭**으로 간다. 2D 탑다운 안은 폐기됐다.

- 움직임은 **멧챠 카멜레온풍** — 작고 날쌘 캐릭터가 톡톡 움직이는 느낌.
- 이동은 **방향키(화살표)** 전용. WASD 는 QWER 스킬과 손이 겹쳐 쓰지 않는다.
- 점프는 스페이스. 회피 수단은 이동 + 점프뿐이다.

### ✅ 결정됨 — 카메라: **고정 각도** (2026-07-31, 사용자 확정)
화면이 도는 일은 없다. 카메라는 정해진 각도로 캐릭터를 따라다니기만 한다.

- **마우스로 시점을 돌리지 않는다.** 마우스룩·마우스 커서 잠금(캡처) 없음.
- 각도는 캐릭터 뒤 위쪽 사선 고정(기본 yaw 0°, pitch -32°, 거리 7m).
  값은 `Player.gd` 의 `cam_yaw_deg` / `cam_pitch_deg` / `cam_distance` 로 조절.
- 화면이 안 도니 **방향키 ↑ = 언제나 화면 위쪽**. 맵 방향 감각이 흔들리지 않는다.
- 캐릭터는 몸만 진행 방향으로 돈다(카메라와 무관).
- 각도 자체를 바꾸고 싶으면 사용자에게 물어본다. 되돌아가는(회전) 카메라는 넣지 않는다.

### ⛔ 이 게임이 아닌 것 — 배그(슈터)가 아니다
기획서에서 "배그처럼"이라고 쓴 곳은 **자기장(안전구역 축소) 딱 하나**다.
조작·카메라·전투 감각은 배그와 무관하다. 아래는 넣지 않는다:

| 넣지 않는 것 | 이유 |
|---|---|
| 우클릭 조준(ADS)·어깨너머 줌 | 총 게임 문법. 이 게임은 마법봉 + QWER 스킬이다 |
| 조준 중 감속 | 위와 같음 |
| 스프린트(달리기 별도 키) | 기획에 없음. 속도는 한 종류 |
| 마우스로 시점 회전(마우스룩) | 카메라는 고정각으로 확정. 화면이 돌지 않는다 |

넣고 싶어지면 **먼저 사용자에게 물어보고 이 문서에 결정으로 남긴 뒤** 구현한다.

## 프로토타입 로드맵
1) 이동+점프 2) 고정 스킬 1개 발사 3) 스킬 에디터(수치판+예산공식) 4) QWER 4슬롯+봇 대전 5) 자기장 축소+5분 타이머 6) 재미 점검.

3단계는 **3a) 수치 슬라이더만 → 3b) 그림판 + 형태 태그 추출** 두 조각으로 쪼갠다.
3a가 돌아가고 재미가 확인된 뒤에 3b를 붙인다.
