# 스킬 크래프트 배틀 (가제) — 게임 기획서

## 한 줄 컨셉
"내가 그린 스킬로 싸운다." 코어 루프 = 그림판에서 스킬 창작 → QWER 4칸에 형평성 있게 배치 → 5분 안에 맞히고 피하는 손맛.

## 코어 설계
- 5v5, 3인칭, PC. 이동 방향키 / 점프 스페이스바 / 스킬 QWER 4슬롯. 5분×3라운드.
- 스킬 제작(심장): 스킬 세팅 창(그림판)에서 모양 그리기 + 발사 형태 + 데미지(1~100) + 범위 설정.
- 형평성 원칙: 데미지 약할수록 쿨 짧게, 셀수록 쿨 길게. 범위 크고 세면 쿨 길고 발동 느림(피하기 쉬움). 범위 작고 세면 발동 빠름(피하기 어려움).
- 맵: 거대한 원룸 한 칸, 소형 인간들이 싸움. 캐릭터/속도는 멧챠 카멜레온풍.
- 자기장: 시간 지나면 배그처럼 안전구역 축소 → 강제 교전.
- 이펙트: 마법봉으로 마법 쓰는 연출. 회피: 이동 + 점프.

## 밸런스 공식
공통 예산 100pt. 비용 = 데미지 + (범위 × 0.6). 남은 예산으로 쿨/발동속도 자동 결정.
실제 수치는 전부 `game/scripts/skill/Balance.gd` 에 있다. 아래는 그 근거만 적는다.

### 쿨타임은 예산에 **곡선**으로 걸린다 (2026-07-31, 밸런스 담당 확정)
`쿨타임 = 0.6초 + 8.4초 × (예산소모율 ^ 1.6)`

지수 1.6 을 쓰는 이유: 선형(지수 1.0)이면 데미지가 클수록 지속 딜(데미지÷쿨)이
계속 좋아져서 **약한 스킬이 일방적으로 손해**였다. 9행 형평성 원칙이 무너진다.
범위 20 고정, 데미지 10~88 의 지속 딜 최대/최소 비 — 지수 1.0 은 2.39배, 1.6 은 1.52배.
(2.0 이면 1.43배로 더 평평하지만 중간 데미지가 최강이 되는 역전이 생겨 1.6 을 골랐다)

### ✅ 결정 — 예산을 넘겨도 만들 수 있다. 대신 대가가 붙는다 (2026-07-31, 밸런스 담당)
예산 초과 시 **저장·발사를 막지 않는다.** 초과분에 비례해 쿨타임과 발동시간이 늘어난다.
- 쿨타임 × (1 + 초과율 × 3.0) · 발동시간 × (1 + 초과율 × 1.5)
- 예: 데미지 100 / 범위 100 = 160pt → 60% 초과 → 쿨 9.0초 × 2.8 = **25.2초**

막지 않는 이유:
1. 8행이 데미지 1~100 을 명시했는데, 초과를 막으면 데미지 100 이 사실상 존재할 수 없다.
   데미지 100 + 최소 범위 1 = 100.6pt 라 무조건 초과이기 때문이다.
2. 9행 형평성 원칙이 "셀수록 쿨 길게"다. 초과분에 쿨을 더 붙이는 건 새 규칙을 만드는 게
   아니라 **기존 원칙을 끝까지 적용하는 것**이다.
3. 거부당하는 것보다 대가를 치르는 쪽이 만드는 재미가 산다.

형평성 검산: 데미지·범위 1~100 전 조합 10,000개를 훑어 `(데미지÷쿨) × 판정반경` 을 비교했다.
| 초과 페널티 | 100pt 이내 최강 | 초과 조합 최강 | 판정 |
|---|---|---|---|
| 없음(종전) | 11.24 | **21.72** | 초과가 2배 이득 — 붕괴 |
| ×1.0 | 11.24 | 13.57 | 아직 이득 |
| ×2.0 | 11.24 | 11.09 | 여기서 뒤집힘 |
| **×3.0 (채택)** | **11.24** | 11.07 | 초과가 이득인 조합 **0개** |

### 밸런스 담당 제안값 — 개발 반영 대기

  150 이면 최대 한 방이 HP 의 2/3 라 반드시 두 번 맞혀야 한다. 5v5 에서 원샷은 과하다.

## ✅ 결정됨 — 그림의 역할: 하이브리드 (2026-07-31)
그림은 **겉모습 + 히트박스 "형태" 태그**까지 담당한다. 세기는 절대 담당하지 않는다.

### 대원칙 (밸런스 안전장치)
> **그림은 모양을 바꾸고, 수치는 세기를 바꾼다.**
> 스킬의 총 유효 판정 면적은 에디터의 `범위` 슬라이더 값으로 **정규화**된다.
> 어떤 그림을 그리든 같은 범위 값이면 총 면적은 같다. 그림은 그 면적을 어떤 모양으로 배분할지만 정한다.
> → 얇은 선 하나로 맵 관통 같은 악용이 원천 차단된다.

### 파이프라인
1. 유저가 그림판(32×32 그리드)에 그림 → 픽셀 마스크
2. 마스크에서 **지표 4개** 계산
   - 채움률 = 칠한 픽셀 / 바운딩박스 면적
   - 종횡비 = 바운딩박스 가로/세로
   - 복잡도 = 둘레² / 면적 (뾰족할수록 큼)
   - 덩어리 수 = 연결 요소(connected components) 개수
3. 지표 → **형태 태그 1개** 판정 (아래 표)
4. 태그 → 히트박스 프리셋 선택, 크기는 `범위` 값으로 정규화
5. 원본 그림은 투사체 스프라이트/이펙트 텍스처로 그대로 사용 (겉모습)

### 형태 태그 표 (판정 조건 수치 확정 — 2026-07-31 밸런스 담당)
판정은 위에서부터 순서대로 본다. 먼저 걸리는 태그가 이긴다.

| 순위 | 태그 | 판정 조건 | 히트박스 형태 | 체감 |
|---|---|---|---|---|
| 1 | 흩어짐 | 덩어리 ≥ 2 | 산탄 다발(작은 원 N개) | 견제형 |
| 2 | 길쭉함 | 종횡비 ≥ 2.5 또는 ≤ 0.4 | 직선 관통형(캡슐) | 조준 어려움, 맞히면 시원함 |
| 3 | 뾰족함 | 복잡도 ≥ 2.5 **그리고** 채움률 < 0.50 | 부채꼴 다단 히트 | 근거리 난사형 |
| 4 | 둥긂 | 나머지 전부(폴백) | 원형 폭발 | 무난, 기본값 |

**뾰족함에 채움률 조건을 더한 이유** — 복잡도(둘레²/면적)는 둘레를 제곱하므로 손떨림에
2차로 반응한다. 검산 결과 손으로 그린 원은 테두리가 한 칸만 울퉁불퉁해도 복잡도가
1.90 → 5.22 로 뛰어 **"원을 그렸는데 부채꼴이 나가는"** 일이 생겼다. 같은 손떨림에서
채움률은 0.67 → 0.61 밖에 안 움직인다. 별·번개·십자는 채움률 0.24~0.48 이라
0.50 문턱으로 원(0.60~0.73)과 깨끗하게 갈린다. 예측 가능해야 그리는 재미가 산다.

애매하면 **둥긂(기본값)** 으로 폴백. 에디터에서 판정된 태그를 실시간으로 보여줘 유저가 예측 가능하게 한다.

### ⚠ 알려진 판정 구멍 (개발 반영 대기)
- **대각선으로 길쭉하게 그리면 길쭉함이 안 나온다.** 종횡비를 축에 나란한 바운딩박스로
  재기 때문에, 대각선 막대는 바운딩박스가 정사각형이라 종횡비가 1.00 이 된다.
  같은 그림을 45° 돌렸을 뿐인데 결과가 달라지는 건 형평성 문제다.
  → 2차 모멘트(PCA) 기반 신장도로 교체하면 해결된다. 검산: 대각선 두께1 = 종횡비 1.00(오답) / PCA 33.9(정답).
- **대각선 점선은 덩어리 수가 0으로 세어진다.** 연결 판정이 4방향이라 대각선으로만
  이어진 픽셀이 끊긴다. → 8방향 연결로 바꾼다.

### 나중 확장 여지 — 그림 커스텀을 더 재미있게 (2026-07-31 밸런스 담당 설계)
픽셀 모양 그대로를 히트박스로 쓰는 완전 B안은 채택하지 않는다.

**지금의 문제**: 32×32 를 공들여 그려도 결과가 태그 4개 중 하나로 환원된다.
그리는 노력과 돌아오는 변화가 안 맞아서, 그림이 "골라 찍는 버튼 4개"처럼 느껴진다.

**확장의 안전 규칙 3개** — 아래 규칙을 지키는 한 무엇을 늘려도 20~24행 대원칙이 안 깨진다.
1. **면적 보존.** 새 파라미터가 어떤 값이 나와도 판정 면적의 합 = `total_area`.
2. **제로섬.** 이득을 주는 축에는 반드시 짝이 되는 손해가 붙고, 둘의 곱/합이 불변이어야 한다.
   (예: 탄을 늘리면 탄 하나가 작아지고 데미지도 나뉜다)
3. **정규화된 지표만 쓴다.** 크기·위치에 안 흔들리는 비율값만 읽는다.
   "크게 그리면 세진다"가 성립하는 순간 그림이 세기를 정하게 되어 대원칙 위반이다.

| 우선순위 | 안 | 그림에서 읽는 것 | 형평성 근거 |
|---|---|---|---|
| 1 | **에디터 실시간 미리보기 + 태그 경계 게이지** | (없음 — 표시만) | 전투 수치를 **하나도 안 바꾼다.** 위험 0 |
| 2 | **태그별 미세 파라미터 4종** | 종횡비·복잡도·덩어리수·채움률 | 전부 면적 보존 + 제로섬 (아래 상세) |
| 3 | **다색 그림(팔레트 2~4색)** | (없음 — 겉모습 전용) | 마스크 값이 0인지 아닌지만 판정에 쓴다. 색은 세기와 무관 |
| 4 | 새 태그(설치·회전) | 무게중심 위치·회전대칭성 | 새 메커니즘이라 **사용자 확인 필요** |
| 5 | 복합 태그(길쭉함+흩어짐 = 연속 관통) | 조합 | 경우의 수가 폭발한다. 4단계 이후 재검토 |

#### 우선순위 2 상세 — 태그별 미세 파라미터
수치는 `Balance.gd` 에 상수로 확정해 뒀다. 아직 배선은 안 됐다.

| 태그 | 읽는 지표 | 바뀌는 것 | 제로섬 짝 | 악용 시나리오와 차단 근거 |
|---|---|---|---|---|
| 길쭉함 | 종횡비 2.5→8.0 | 길이:폭이 4:1 → 21:1 | 길어지면 그만큼 얇아진다(면적 고정) | *"1픽셀 선으로 맵 관통?"* → 길이 = 3.0×√면적 이라 면적의 **제곱근**에만 비례한다. 범위 100 에서도 10.4m 이고, 폭 하한 0.22m 에 걸리면 길이를 되레 줄인다. 얇을수록 정면 단면이 작아 조준이 어려워지는 것이 대가다 |
| 뾰족함 | 복잡도 2.5→12.0 | 부채꼴 55°→130°, 탄 2→5발 | 좁으면 반지름이 길고, 넓으면 짧다(면적 고정). 탄이 늘면 한 발 데미지가 나뉜다 | *"55°로 좁혀서 저격?"* → 부채꼴 반지름은 √(면적×360/각도/π) 라 면적에 묶여 있고, 사거리는 여전히 `범위` 값만 정한다. 좁힌다고 더 멀리 못 간다 |
| 흩어짐 | 덩어리 수 | 탄 수 2~6발 | 탄 하나의 면적 = 총면적÷N, 데미지 = 총데미지÷N | *"덩어리를 많이 그리면 이득?"* → 탄 N발의 각지름 합은 √N 에 비례해 커진다. 그래서 **퍼짐각도 √N 에 비례해 넓힌다.** 그러면 퍼짐 안에서 맞을 확률이 N 과 무관해진다. 이 보정을 빼면 많이 그릴수록 무조건 이득이 되어 깨진다 |
| 둥긂 | 채움률 < 0.35 (속이 빈 그림) | 최대 2명 관통 | 총 데미지를 관통 수로 나눈다 | *"관통이 공짜 이득?"* → 한 명만 맞히면 데미지가 절반이라 **손해**다. 일직선에 두 명이 겹쳤을 때만 본전. 순수 제로섬 |

관통(둥긂)은 새 메커니즘이라 **사용자 확인 필요**. 나머지 셋은 기존 프리셋의 파라미터
조정이라 47행 「태그별 미세 파라미터를 그림에서 더 뽑는」 확장 범위 안이다.

## ✅ 결정됨 — 엔진/시점: Godot 4, **3D 3인칭** (2026-07-31, 사용자 확정)
프로토타입부터 **3D 3인칭**으로 간다. 2D 탑다운 안은 폐기됐다.

- 움직임은 **멧챠 카멜레온풍** — 작고 날쌘 캐릭터가 톡톡 움직이는 느낌.
- 이동은 **방향키(화살표)** 전용. WASD 는 QWER 스킬과 손이 겹쳐 쓰지 않는다.
- 점프는 스페이스. 회피 수단은 이동 + 점프뿐이다.

### ✅ 결정됨 — 카메라: **고정 각도** (2026-07-31, 사용자 확정)
화면이 도는 일은 없다. 카메라는 정해진 각도로 캐릭터를 따라다니기만 한다.

- **마우스로 시점을 돌리지 않는다.** 마우스룩·마우스 커서 잠금(캡처) 없음.
- 각도는 캐릭터 뒤 위쪽 사선 고정(기본 yaw 0°, pitch -32°, 거리 7m).
  값은 `Player.gd` 의 `cam_yaw_deg` / `cam_pitch_deg` / `cam_distance` 로 조절.
- 화면이 안 도니 **방향키 ↑ = 언제나 화면 위쪽**. 맵 방향 감각이 흔들리지 않는다.
- 캐릭터는 몸만 진행 방향으로 돈다(카메라와 무관).
- 각도 자체를 바꾸고 싶으면 사용자에게 물어본다. 되돌아가는(회전) 카메라는 넣지 않는다.

### ⛔ 이 게임이 아닌 것 — 배그(슈터)가 아니다
기획서에서 "배그처럼"이라고 쓴 곳은 **자기장(안전구역 축소) 딱 하나**다.
조작·카메라·전투 감각은 배그와 무관하다. 아래는 넣지 않는다:

| 넣지 않는 것 | 이유 |
|---|---|
| 우클릭 조준(ADS)·어깨너머 줌 | 총 게임 문법. 이 게임은 마법봉 + QWER 스킬이다 |
| 조준 중 감속 | 위와 같음 |
| 스프린트(달리기 별도 키) | 기획에 없음. 속도는 한 종류 |
| 마우스로 시점 회전(마우스룩) | 카메라는 고정각으로 확정. 화면이 돌지 않는다 |

넣고 싶어지면 **먼저 사용자에게 물어보고 이 문서에 결정으로 남긴 뒤** 구현한다.

## 프로토타입 로드맵
1) 이동+점프 2) 고정 스킬 1개 발사 3) 스킬 에디터(수치판+예산공식) 4) QWER 4슬롯+봇 대전 5) 자기장 축소+5분 타이머 6) 재미 점검.

3단계는 **3a) 수치 슬라이더만 → 3b) 그림판 + 형태 태그 추출** 두 조각으로 쪼갠다.
3a가 돌아가고 재미가 확인된 뒤에 3b를 붙인다.
