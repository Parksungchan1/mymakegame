# 개발(developer) 진행 메모

## 2026-07-31 — 로드맵 3b: 그린 그림이 그대로 날아간다

사용자 승인으로 기획서의 "3a 재미 확인 후 3b" 게이트를 건너뛰고 바로 붙였다.
(사용자가 "그리는대로 이제 날라갈 수 있는건가?" 라고 두 번 물었고, 지금 붙이라고 결정함)

### 겉모습 — 그림이 그대로 스프라이트가 된다
`Projectile.gd` 가 32×32 마스크를 `Image`(RGBA8)로 만들어 `Sprite3D` 로 띄운다.
칠한 픽셀만 스킬 색, 나머지는 투명. `TEXTURE_FILTER_NEAREST` 로 픽셀 느낌을 살렸고
빌보드라 고정각 카메라에서 항상 정면으로 보인다. 크기는 판정 크기에 맞춘다.
그린 게 없으면(빈 그림) 예전처럼 밋밋한 구로 그린다.

기획서 35행 "원본 그림은 투사체 스프라이트/이펙트 텍스처로 그대로 사용" 을 그대로 구현한 것이다.

### 판정 — 태그가 고른 프리셋. 픽셀 모양이 아니다
`Player.gd` 가 저장된 태그를 믿지 않고 `Balance.tag_from_mask()` 로 **매번 다시 뽑는다.**
기획 담당이 판정 임계값을 바꾸면 이미 저장된 스킬에도 즉시 반영돼야 하기 때문이다.

| 태그 | 히트박스 | 발 수 | 한 발 데미지 |
|---|---|---|---|
| 둥긂 | 구 | 1 | 전부 |
| 길쭉함 | 캡슐(진행 방향으로 누움) | 1 | 전부 |
| 뾰족함 | 작은 구를 90° 부챗살로 | 3 | ÷3 |
| 흩어짐 | 작은 구를 14° 안에 | 5 | ÷5 |

**발 수는 Balance 가 정한다.** `damage_per_hit` 의 ÷3·÷5 와 발 수가 짝이라
여기서 발 수만 바꾸면 총 데미지가 어긋난다. `Projectile` 은 "한 발"만 알고,
나누는 건 `Player._shoot()` 이 한다.

캡슐은 Godot 에서 Y축으로 서 있어서, 몸을 `Basis.looking_at(dir)` 로 돌린 뒤
`CollisionShape3D` 를 X축 -90° 회전해 진행 방향(-Z)으로 눕혔다.

### Balance.gd 에 추가한 상수 (기획 담당 조정 지점)
- `SCATTER_SPREAD_DEG = 14.0` — 산탄이 퍼지는 각도. **기획서에 수치가 없어 개발이 임시로 잡았다.**
- `CONE_PELLETS = 3` — 부채꼴을 나눌 탄 수. `damage_per_hit` 의 뾰족함 ÷3 과 맞물린다.
- 부채꼴 히트박스에 `pellets` / `pellet_radius` 추가. 셋을 합친 면적이 `total_area` 와 같게 잡았다
  (흩어짐이 이미 쓰던 방식과 동일). 기존 `radius`(부채꼴 반경)는 표시용으로 남겼다.

### 제작창 표시 되돌림
3a 때 "그림은 아직 전투에 반영 안 됨" 이라고 적어뒀던 안내를 걷어냈다. 이제 사실이 아니다.
대신 오해를 막는 문장으로 바꿨다 — "그림은 겉모습과 형태를 정합니다. 세기는 수치가 정합니다."
`_describe_box` 의 부채꼴 설명도 "부채꼴 90° — 작은 탄 3발" 로 실제와 맞췄다.

### 검증 (헤드리스)
그림 4종을 만들어 태그 판정 → 장착 → 발사 → 명중까지 확인했다.

| 그림 | 태그 판정 | 히트박스 | 발사 | 명중 데미지 |
|---|---|---|---|---|
| 원 | 둥긂 ✓ | sphere | 1발 | 30.0 |
| 세로 막대 | 길쭉함 ✓ | capsule | 1발 | 30.0 |
| 점 3개 | 흩어짐 ✓ | scatter | 5발 | 30.0 (전탄 명중) |
| 십자+가지 | 뾰족함 ✓ | cone | 3발 | 10.0 (5m 에선 1발만 명중) |

뾰족함이 5m 에서 1발만 맞는 건 90° 부챗살이라 그렇다. "근거리 난사형" 이라는
기획서 체감 설명과는 맞지만, **전탄 명중 거리가 너무 짧은 게 아닌지는 QA·기획 확인이 필요하다.**

## 2026-07-31 — 로드맵 3a: 에디터 수치가 실제 발사에 반영

사용자가 "스킬은 사용자가 그림을 그리고 그게 날아가는 형태 아니냐"고 물었다. 맞다.
다만 2단계까지는 고정 수치라 그림도 슬라이더도 전투에 반영되지 않았다.
기획서 87~88행의 3a → 3b 순서에 따라 **수치부터** 이었다.

### 한 일
- `Player.gd` 가 `SkillDB.get_slot("Q")` 에서 이름·데미지·범위·색을 읽는다.
  하드코딩 값은 `fallback_*` 로 남겨 슬롯이 비었을 때만 쓴다.
- `SkillDB.slot_changed` 를 구독한다 → 제작창에서 저장하면 **다음 발사부터 바로 반영**.
  (제작창은 트리를 멈추지만 시그널 콜백은 정지와 무관하게 돈다)
- **그림(mask)과 저장된 태그는 일부러 안 읽는다.** 형태 태그는 항상 `둥긂` 고정이다.
  그림을 겉모습·히트박스로 쓰는 건 3b 다.

### 에디터 표시를 사실대로 고침
제작창이 그림에서 판정한 태그로 전투 수치를 계산해 보여주고 있었다.
그대로 두면 화면에는 "부채꼴 90°"가 뜨는데 실제로는 구가 날아간다 — 지어낸 값이다.
- 전투 수치는 `TAG_ROUND` 기준으로 계산하도록 바꿈 (= 실제로 나가는 것과 일치)
- 태그 표시는 `형태: 뾰족함 (3b 예정 — 지금은 둥긂으로 나감)` 으로 명시
- 상단에 "지금(3a)은 데미지·범위 수치만 전투에 반영됩니다" 안내 한 줄 추가

### 검증 (헤드리스)
- 기본 슬롯 반영: 불꽃탄 22/18 → 쿨 4.94초 · 반경 0.95m, 명중 데미지 **22**
- 슬롯을 5/4 로 저장 → 플레이어가 즉시 갱신 (쿨 **2.28초** · 반경 **0.63m**), 명중 데미지 **5**
- 메인 씬 헤드리스 부팅 오류 0건
- 검증이 `user://skills.json` 을 덮어써서 지우고 기본 4개(불꽃탄·관통창·산탄·대폭발) 복원 확인

### ⚠ 기획 담당에게 — 예산 초과 스킬이 그대로 나간다
제작창은 예산 초과 시 빨간 글씨로 "초과!"를 띄우지만 **저장도 발사도 막지 않는다.**
데미지 100 / 범위 100 이면 비용 160pt 인데, `spent_ratio` 가 1.0 으로 clamp 돼
쿨타임이 최대 12초에서 멈춘다. 즉 **100pt 를 지킨 스킬보다 이득이다.**
기획서 9행 「형평성 원칙」에 어긋나지만, 막는 규칙이 기획서에 없어서
코드가 임의로 만들지 않았다. 3a 를 굴려보고 어떻게 할지 정해야 한다.

## 2026-07-31 — 로드맵 2단계: 고정 스킬 1개 발사

크래시 세션이 건너뛴 2단계를 순서대로 되돌아와 구현했다.
3단계(에디터) 코드는 이미 있지만 **일부러 쓰지 않았다.** 2단계가 3단계에 기대면
로드맵을 건너뛴 것과 같아진다. 수치는 `Player.gd` 에 직접 박아뒀고,
3단계에서 `SkillDB.get_slot("Q")` 로 바꿔 끼우면 된다.

### 새 파일
- `game/scripts/skill/Projectile.gd` — 투사체(Area3D).
  속도·사거리·판정 반경·데미지를 **스스로 정하지 않는다.** 쏘는 쪽이 `Balance.derive()`
  결과를 `configure()` 로 넘겨주고 그대로 쓴다. 노드(판정구·빛나는 구·광원)는 코드로 짓는다
  — 판정 반경이 밸런스 계산 결과라 매번 달라져서 `.tscn` 으로 고정할 수 없다.
  구현한 히트박스는 **둥긂(구체) 하나뿐**이다. 길쭉함/뾰족함/흩어짐은 3단계에서 붙인다.
- `game/scripts/Dummy.gd` — 허수아비. 맞으면 체력이 줄고 색이 튀고, 0이면 쓰러졌다가 2.5초 뒤 다시 선다.
  머리 위 `Label3D` 로 체력을 보여준다. **봇이 아니다** — 움직이지도 반격하지도 않는다.

### 고친 파일
- `game/scripts/Player.gd`
  - Q → `발동시간` 대기 → 발사 → `쿨타임`. 세 값 모두 Balance 가 정한 것을 그대로 쓴다.
  - **발동 중에 느려지게 하지 않았다.** 기획서가 "조준 중 감속"을 금지했고,
    피하는 수단이 이동·점프뿐이라 발동 중에도 그게 살아 있어야 한다.
  - `aim_direction()` / `cooldown_left()` 공개 — HUD 가 붙으면 쓸 창구.
  - 🐞 **버그 수정: 캐릭터가 뒤를 보고 달렸다.** `_face()` 가 몸의 **+Z** 를 진행 방향에
    맞추고 있었는데, Godot 의 앞은 -Z 고 `Player.tscn` 의 얼굴 메시도 -Z 쪽에 붙어 있었다.
    `atan2(dir.x, dir.z)` → `atan2(-dir.x, -dir.z)`. 발사 방향이 여기에 걸려서 같이 고쳤다.
- `game/scenes/Player.tscn` — 마법봉(막대 + 빛나는 끝 + `Muzzle`) 추가.
  기획서 12행 "마법봉으로 마법 쓰는 연출". 투사체는 이 끝에서 나간다.
- `game/scenes/Arena.tscn` — 허수아비 3개 (정면 9m / 좌측 / 우측).
- `game/project.godot` — 2행 주석에 `배그식` 이 아직 남아 있어 정정.
  감시자가 `Player.gd` 만 걷어내고 여기를 놓쳤다.

### 🐞 Godot 함정 (다시 밟지 말 것)
`Projectile` 에 `monitorable = false` 를 넣었더니 **허수아비·벽에 영영 안 맞았다.**
"이 투사체를 감지할 다른 Area 가 없으니 꺼도 되겠지" 하고 넣은 최적화였는데,
Godot 4.7 브로드페이즈가 monitorable 이 꺼진 Area 를 정적으로 취급해서
**StaticBody3D 와 아예 짝을 만들지 않는다.** 정적↔정적은 쌍이 안 생긴다.

증상이 고약하다 — 레이어/마스크/모양 전부 정상이고 `get_shape_owners()` 도 멀쩡한데
`get_overlapping_bodies()` 만 계속 0이다. 같은 자리에 플레인 Area3D 를 놓으면 잡힌다.
속성을 하나씩 바꿔가며 좁혀서 찾았다. `Projectile.gd` 에 주석으로 못박아뒀다.

### 검증 (Godot 4.7.1 헤드리스)
`--headless --import` 오류 0건. 그리고 임시 하네스로 실제 발사를 돌려 확인했다(검증 후 삭제):
- 표적 5m 앞에서 발사 → **10프레임 만에 명중, 체력 100 → 78** (데미지 22)
- 명중 20프레임 뒤 투사체 정리됨 (누수 없음)
- Q 입력 → 약 21프레임(발동시간 0.31초) 뒤 발사 — 입력부터 끝까지 이어짐
- 쿨타임 중 재입력 → 발사 안 됨 (차단 확인)

계산된 전투 수치(데미지 22 / 범위 18, 태그 둥긂):
쿨타임 4.94초 · 발동 0.31초 · 속도 25.1 m/s · 사거리 12.7m · 판정 반경 0.95m

### 기획 담당(game-designer)에게 넘길 것
**쿨타임 4.94초는 직접 쏴보면 길게 느껴질 수 있다.** 예산 공식(`cost = 22 + 18×0.6 = 32.8`)이
그대로 뱉은 값이라 코드에서 임의로 줄이지 않았다. 수치는 기획 담당 영역이다.
플레이 확인 뒤 `Balance.COOLDOWN_MIN/MAX` 를 조정할지 판단이 필요하다.
