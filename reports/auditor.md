# 감시자(auditor) 검사 기록

## 2026-07-31 (2차) — 검사 대상: 로드맵 2단계 "고정 스킬 1개 발사"

**판정: 통과** (확인 필요 2건 첨부)

### ✅ 통과
- **로드맵 순서 지킴** — 1차 감사에서 반려했던 "2단계 건너뜀"이 해소됐다.
  2단계가 3단계 코드(`SkillDB`·`SkillEditor`)에 기대지 않고, 수치를 `Player.gd` 에
  직접 박아 독립적으로 돈다. 3a/3b 를 앞당겨 쓰지 않았다.
- **기획서 근거 있음** — 스킬 QWER(7행) 중 Q 하나만, 마법봉 연출(12행),
  밸런스 공식(15행), 히트박스 면적을 `범위` 값으로 정규화(20~24행) 전부 기획서대로다.
- **`✅ 결정됨` 무단 변경 없음** — 카메라 고정각, 3D 3인칭, 방향키 전용 전부 그대로다.
  발사를 붙이면서 마우스 조준을 넣고 싶어질 자리인데 넣지 않았다.
- **금지 항목 안 들어옴** — 「넣지 않는 것」 표 4종(ADS·어깨너머 줌·조준 중 감속·
  스프린트·마우스룩) 어느 것도 없다. 발동 중 감속도 없다(기획서가 금지한 항목).
- **판정 면적 정규화 지켜짐** — 투사체가 반경을 스스로 정하지 않고
  `Balance.derive()` 의 `hitbox.radius` 를 받아 쓴다. 코드가 세기를 만들 수 없다.
- **문서-코드 일치** — `project.godot` 2행에 남아 있던 `배그식` 주석을 정정했다.
  1차 감사 때 `Player.gd` 만 보고 놓친 곳이다.

### ⚠ 확인 필요 (사용자 판단)
1. **허수아비(`Dummy.gd`) 3개는 기획서에 없다.** 4단계의 "봇"도 아니다.
   다만 데미지가 들어가는지 확인할 대상이 없으면 2단계를 검증할 방법이 자체가 없어,
   **검증용 표적**으로 판단해 통과시켰다. 움직이지도 반격하지도 않아 게임 규칙에
   영향을 주지 않는다. 4단계에서 진짜 봇이 들어오면 삭제 대상이다.
   → 표적을 두는 것 자체가 싫다면 알려주면 걷어낸다.
2. **쿨타임 4.94초** — 예산 공식이 뱉은 값 그대로다. 개발이 임의로 줄이지 않은 건 옳다.
   다만 직접 쏴보면 길게 느껴질 수 있다. 조정 여부는 **기획 담당 판단**이지 개발이 아니다.

### 참고 — 이번엔 반려하지 않은 이유
1차 감사의 반려 사유 3건(배그화 / 시점 무단 변경 / 로드맵 건너뜀)이 모두 재발하지 않았다.
기획서에 없는 것을 넣은 건 허수아비 하나뿐이고, 그건 검증 수단이라 사유를 남기고 통과시켰다.


## 2026-07-31 — 검사 대상: 크래시로 유실될 뻔한 미커밋 작업물 (3D 전환 + 스킬 에디터)

**판정: 반려** → 사용자 확인 후 일부 정정하여 통과

### ⛔ 위반
- **게임 전체를 배그(슈터)식으로 만듦** — 기획서 근거 없음.
  기획서의 `배그처럼`은 11행 `자기장: 시간 지나면 배그처럼 안전구역 축소` 한 곳뿐이고,
  그 비유는 **안전구역에만** 걸린다. 조작·카메라로 확대 적용한 것은 확대해석.
  - `Player.gd` 우클릭 조준(ADS) `is_aiming()` / 어깨너머 줌 `cam_distance_aim`
  - `Player.gd` 조준 중 감속 `aim_speed`, 스프린트 `sprint_speed`
  - `project.godot` 입력 `aim`(우클릭), `sprint`
  - 주석에 "배그식"이라 직접 명시(2행, 13행)
  → 조치: **전부 제거 완료.** 이 게임은 마법봉 + QWER 스킬 게임이지 총 게임이 아니다.

- **프로토타입 시점을 임의로 갈아엎음** — 당시 기획서 54행은 `프로토타입, 2D 탑다운`이었는데
  사용자 승인·결정 기록 없이 3D로 전환하고 커밋된 `Main.tscn`을 삭제함.
  코드를 먼저 바꾸고 문서를 안 맞춘 전형적 사례.
  → 조치: **사용자가 3D 3인칭으로 확정.** 결과적으로 방향은 맞았으나 **절차가 틀렸다.**
     기획서에 `✅ 결정됨` 항목으로 정식 기록함.

- **로드맵 순서 건너뜀** — 2단계(고정 스킬 1개 발사)를 하지 않고 3b(그림판 `SkillCanvas.gd`)까지 감.
  기획서는 `3a가 돌아가고 재미가 확인된 뒤에 3b를 붙인다`고 못박음.
  → 조치: 코드는 보존하되 **2단계로 되돌아가서 순서대로 진행**할 것. STATUS 상단에 명시함.

### ⚠ 확인 필요
- **카메라 조작 방식** — 배그 요소는 걷어냈지만 마우스로 카메라를 돌리는 방식은 남겨뒀다.
  3D 3인칭이면 통상적이나 기획서에 명시된 바 없다. 멧챠 카멜레온풍이라면 고정 각도
  추적 카메라가 맞을 수도 있음. → 사용자 확인 필요.
- **이동 속도 수치** — 2D 때 `280 px/s`는 3D에서 의미가 없어 `6.0 m/s`로 새로 잡았다.
  멧챠 카멜레온풍 체감에 맞는지는 직접 플레이해봐야 안다.

### ✅ 통과
- `game/scripts/skill/` 4개 파일(`Balance.gd` `SkillDB.gd` `SkillCanvas.gd` `SkillEditor.gd`)
  — 기획서 17~48행(하이브리드 결정, 형태 태그 표)에 근거함. 3D 의존 코드 0줄.
  태그별 타격 분배(흩어짐 ÷5, 뾰족함 ÷3)도 기획서 형태 태그 표와 일치.
- 방향키 전용 이동 — 기획서 7행 `이동 방향키` 근거. WASD 배제도 QWER 4슬롯과의 충돌 회피로 타당.
- 점프(스페이스) — 기획서 7행·12행 `회피: 이동 + 점프` 근거.
